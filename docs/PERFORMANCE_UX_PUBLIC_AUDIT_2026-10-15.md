# RunMeter パフォーマンス・UI/UX・公開データ監査

監査日: 2026-10-15（日本時間）。既存の作業ツリーを保持し、Web・ローカルRelay・Windows版・公開候補ファイルとGit履歴を検査した。

## 修正内容

| 分野 | 問題と対応 |
| --- | --- |
| DB書込 | 取得処理とHTTP処理が同じ計測を重複保存していた。同一スナップショットの保存を省略し、未変化の10回ポーリングで追加書込0回を実DBで確認した。 |
| 履歴検索 | サービス横断の時刻検索に索引を追加。`EXPLAIN QUERY PLAN`で索引の利用を確認した。 |
| 状態取得 | 非表示のGeminiをダッシュボード更新で取得しない。Codexの状態確認は10秒間共有し、明示更新・通知は即時取得する。 |
| CLI表示 | Claudeの送信と既存statusLine処理を並列化。元のstatusLineがない場合は不要な資格情報保管庫の呼出しを省く。 |
| 初期読込 | 実行・アクティビティ・エージェント・予算の補助UIを、必要になった時点で読み込む。ビルドにしか使わないshadcn CLIを開発依存へ移した。 |
| スマホ | リセット日時を全幅に配置し、接続・公式画面ボタンとの圧迫を解消。タッチ操作領域を44px以上にした。 |
| キーボード | メニューの閉じるボタンを表示し、閉じた後は起点へフォーカスを戻す。利用率へのスキップリンクとフォーカス表示を追加した。 |
| 履歴の読取り | マトリクスに数値を表示し、新しい日付から並べる。正確な値を確認できる日別表を追加し、表のスクロールもキーボードで操作可能にした。 |
| 視認性 | 入力境界と文字のコントラストを改善。マトリクスは背景の濃度に応じ文字色を変える。 |
| 低い画面 | 検索ダイアログに画面高の上限と閉じるボタンを追加し、横向き画面でも操作可能にした。 |
| コピー操作 | クリップボード拒否時の未処理例外を修正し、コピー完了・失敗と復旧方法を日本語で表示する。 |
| 案内 | 個人GitHubアカウントへの固定リンクを除去し、アプリ内の`/guide`に接続手順と端末制約をまとめた。 |
| 依存 | Next.js / eslint-config-nextを指定の16.3系内の16.3.8に更新。互換範囲の依存を更新し、本番依存のnpm監査を0件にした。 |

利用率と次のリセット日時を画面の主情報として維持し、製品にデモデータは追加していない。非表示タブではリセット時計を停止する。実アカウントの認証・Claudeの設定は検証で変更していない。

## 公開する情報の整理

公開候補に対する検査で、実トークンや私用メールは検出されなかった。会社名と会社の公開URLは開発元表記として残した。

元の3コミットには作成者・コミッターの私用メールと個人ユーザー名が残っている。現在のファイルやGit設定を直すだけでは過去の情報は消えないため、元の履歴をそのまま公開する方式は採用していない。

公開用ソースは`.public-release/RunMeter`へ作成する。ignore対象・元の`.git`・remote・hooksを含めず、`RunMeter contributors / noreply@example.invalid`による単一の初回コミットにする。元の開発リポジトリの履歴や公開設定は変更しない。

- `.env`、認証情報、端末内DB、ログ、証明書、ビルド・テスト生成物を除外。
- `npm run check:public`で値を表示せず検出種別と件数だけを確認。
- `node scripts/check-public-data.mjs --history`でコミット情報も検査。
- 既存出力先の上書き、シンボリックリンクやジャンクション、パス逸脱、秘密値を含むソースの出力を拒否。

検査は既知のパターンに基づくもので、あらゆる秘密情報や画像内の情報の不存在を保証するものではない。検査範囲と再作成手順は[公開用リポジトリの手順](PUBLIC_REPOSITORY.md)を参照。

## 配布に関する制約

標準Relayは同じPC専用。スマートフォンから別PCの利用データを読む機能はない。Windows版は公開済みWeb UIを読み込むため、Web修正はデプロイ後に利用者へ反映される。

SetupとRunMeter本体は未署名で、検証用の成果物として扱う。Windowsの署名とクリーン環境での実インストール確認は前回監査から継続する配布条件。本作業ではGitHubへのpush、公開設定の変更、本番へのデプロイは行っていない。
