# RunMeter リリース前監査

監査日: 2026-09-26（日本時間）

対象: `main` の `7e02167` を基点とする現在の作業ツリー。監査開始時から存在した未コミット変更を保持して検証した。公開済みVercel環境への反映、Gitへのコミット・push、公開リリースの作成は行っていない。

## 判定

コード上で再現した問題を修正し、Webとローカル連携のテスト・本番ビルドを通過した。Windows版もインストーラーを生成できる。ただしWindows一般配布の承認条件であるコード署名と、クリーンなWindows環境での導入・更新・削除確認は未完了。現時点の成果物は社内検証用として扱う。

## 修正した問題

| 重要度 | 問題 | 修正と検証 |
| --- | --- | --- |
| 高 | Next.js 16.3.1等の依存ライブラリに公開済み脆弱性 | Next.js / eslint-config-nextを16.3.6へ更新。互換範囲の依存も更新し、WebとDesktopの`npm audit`は0件 |
| 高 | 切断後に古い取得処理が終了すると接続済み状態が復活 | Codex・HTTP操作の世代を照合。切断前の結果を保存・表示しない回帰テストを追加 |
| 高 | 閉じた接続ダイアログの遅延401で、新しいペアリングまで消える | IndexedDBの読書きトランザクション内で対象トークンを照合。破棄済みダイアログの結果も反映しない |
| 高 | Claudeの連携設定保存中にユーザーが編集すると、その変更を上書き | 設定操作の直列化、資格情報保存後の再読込、statusLineの競合検出、対象ファイル照合を追加 |
| 高 | ProviderやOSの例外メッセージに秘密情報・ローカルパスが含まれうる | ブラウザには既知の安全なメッセージのみ返す。テスト用の秘密文字列を含む例外で漏洩しないことを確認 |
| 中 | 利用状況の取得失敗でも最新の取得時刻・新しい履歴として保存 | 最終成功時刻を保持。エラー・接続中のキャッシュを新規観測として記録しない |
| 中 | Claude再接続失敗で既存の取り込みトークンを失効 | 有効な既存トークンを維持し、期限切れだけ更新 |
| 中 | Codex App Serverの初期化失敗でプロセスが残る、不正RPCやstdinエラーで停止 | 子プロセス回収、入力検証、エラーハンドリングと再試行を追加 |
| 中 | 日別履歴の重複加算、無効な日付・過大な整数 | 日付ごとに置換・統合。無効な日付と安全に表現できないトークン数を除外 |
| 中 | SQLiteに保存した日別履歴を読み戻さず、切断やAPI取得期間縮小で画面から消える | 保存履歴を統合し、再起動後も表示。応答は直近90記録日・最大180サービス別セルに制限 |
| 中 | 自動更新を停止しても即時取得・タブ再表示時の取得が走る | 停止中の自動取得を抑止。再開時と明示した接続操作では更新する |
| 中 | 過ぎたリセット日時が「あと1分以内」のまま | 現在時刻で表示を更新し、経過後は「リセット時刻を過ぎました・更新待ち」と明示 |
| 中 | Claude連携後も開いたダイアログに「未接続」が残る | 手順型の認証待ちも状態確認対象にし、親画面の最新状態を反映 |
| 中 | Windows終了時にRelay終了を待たず、または終了しきらず常駐する | 終了処理完了を待ってからアプリを終了。隔離したElectron実行で確認 |
| 中 | Windows版のオフライン時の復帰導線、リダイレクト・サブフレーム制御 | 再試行画面と通知領域からの再読み込み、信頼する遷移先と権限の制限を追加 |
| 中 | 開発起動でもWindowsへの自動起動登録が行われる | 自動起動登録をパッケージ版に限定 |
| 中 | アンインストールしてもClaudeのRunMeter用statusLineが残る | 元の設定の復元を待ってからSquirrelの終了処理へ進む。利用者の独自編集と保存済み利用履歴は保持 |
| 低 | 6桁以外のコードでもペアリング試行を消費する、閉じたダイアログからフォーカスが戻らない | 6桁の数字のみ送信し、閉じると接続ボタンへフォーカスを戻す |
| 低 | 日数が違っても履歴が「過去7日間」と表示される | 実際の記録日数を表示。マトリクス列数も日付数に合わせる |
| 低 | 認証情報の保存先の説明がCodexの実装と異なる | Codex公式アプリが認証を管理し、Claudeは公式statusLineから値を取得する説明に統一 |
| 低 | 入れ子のnode_modulesや署名用証明書がGit対象になりうる | node_modules、テスト成果物、PFX/P12を除外 |

Windows依存はElectron 43.7.5、同梱Node.js 24.21.0。Forge 7との互換性を保ち、ZIP展開のみElectron公式の代替`@electron-internal/extract-zip@1.0.5`へ置換した。TypeScript CLIは7.0.2、Next.js/ESLint互換APIは6.0.2を維持している。

## 公開前に残る確認

1. Windowsコード署名。現状のSetup.exeとRunMeter.exeは`NotSigned`。署名証明書を設定して再生成し、両方の署名を確認する。署名後もSmartScreenの評価は別途確認する。
2. クリーンなWindows 10/11で新規導入、既存版からの更新、Windowsログイン後の自動起動、削除を確認する。監査中は利用中のPCへインストールし直していない。
3. 実アカウントでCodexとClaudeを接続し、公式画面の利用率・リセット日時との一致を確認する。自動テストでは実トークンを使わず、利用中のCLI認証やClaude設定を変更していない。
4. 検証済み変更をGitに保存して本番Webへ反映する。Desktopは公開済みWeb UIを読み込むため、ローカルWeb修正はデプロイ後に反映される。

Codex CLI・Claude Codeは利用者のPCに別途必要。日別トークン数は公式データが取得できる範囲だけを表示する。履歴は端末・サービス単位であり、同じサービスの複数アカウントは分離しない。標準Relayは同じPC専用で、スマホから別PCへLAN接続する機能は含まれない。
